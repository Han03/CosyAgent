## 1. 总览



| 项目       | 说明                                                                                |
| -------- | --------------------------------------------------------------------------------- |
| Base URL | `http://<host>:<port>`（默认 `8080`，本机冒烟示例用 `28080`）                                 |
| 响应格式     | 统一 JSON：`{ "code": 0, "message": "success", "data": {...} }`，`code=0` 表示成功        |
| 字符编码     | UTF-8                                                                             |
| 鉴权       | 配置 `COSY_AGENT_API_KEY` 后，`/api/**` 所有请求需携带请求头 `X-API-Key: <key>`；未配置则不鉴权（本地开发默认） |
| 状态码      | 业务错误通过 `code` 表达（HTTP 恒为 200 或 401）；未处理异常返回 HTTP 500                              |
| 数据模型     | 见 [7. 数据模型](#7-数据模型)                                                              |

接口清单：



| 方法   | 路径                                 | 说明                             | Step |
| ---- | ---------------------------------- | ------------------------------ | ---- |

## 2. 统一响应结构



```
// 成功

{ "code": 0, "message": "success", "data": { ... } }

// 失败（业务错误）

{ "code": 10002, "message": "工具不存在", "data": null }

// 鉴权失败（HTTP 401）

{ "code": 401, "message": "无效或缺失的 X-API-Key", "data": null }

// 未处理异常（HTTP 500）

{ "code": 500, "message": "系统内部错误", "data": null }
```

## 3. 鉴权说明



* 环境变量 `COSY_AGENT_API_KEY` 设置非空后，鉴权过滤器自动生效：拦截 `/api/**`（`/actuator/**` 与静态资源放行）；

* 校验请求头 `X-API-Key` 与配置值一致，否则返回 `401` + 上述统一错误结构；

* 未配置（默认）时不装配过滤器，接口完全开放，便于本地开发与测试；

* 生产建议：配合 Docker/K8s 的 Secret 注入（见 `docker-compose.yml` / `deploy/k8s/cosy-agent.yaml`）。

## 4. 错误码



| code  | 含义       | 场景                                   |
| ----- | -------- | ------------------------------------ |
| 0     | 成功       | —                                    |
| 400   | 参数校验失败   | 请求体缺必填字段（如 `sessionId`/`message` 为空） |
| 401   | 未授权      | 缺少或错误的 `X-API-Key`                   |
| 500   | 系统内部错误   | 未捕获异常                                |
| 10001 | 智能体组件未就绪 | Agent 未初始化                           |
| 10002 | 工具不存在    | 模型调用了未注册工具                           |
| 10003 | 工具执行失败   | 工具运行抛异常                              |
| 10004 | 模型调用失败   | LLM 调用异常（含重试耗尽）                      |
| 10005 | 记忆访问失败   | Redis 记忆读写失败（内部降级，通常不对外）             |
| 10006 | 向量检索失败   | 知识库检索失败                              |
| 10007 | 请求过于频繁   | 触发限流                                 |
| 10008 | 任务不存在    | 按 taskId 查询 / 恢复不存在的任务               |
| 10010 | 模型不可用     | 指定模型平台未注册（`X-Cosy-Model: platform/model` 平台不存在） |
| 10011 | 配置保存失败    | 模型路由配置持久化失败（store 写入异常）            |

## 5. 接口明细

### 5.1 POST `/api/agent/chat` — 对话入口

请求：



```
{ "sessionId": "s1", "message": "现在几点？" }
```



| 字段        | 类型     | 必填 | 说明               |
| --------- | ------ | -- | ---------------- |
| sessionId | string | 否  | 会话 ID（记忆分层的命名空间）；**缺省时服务端自动生成并随响应返回**（首条消息触发创建，会话名=首条消息） |
| message   | string | 是  | 用户输入             |

请求头（可选）：

| 请求头           | 取值                 | 说明                                                                 |
| -------------- | ------------------ | ------------------------------------------------------------------ |
| `X-Cosy-Mock`  | `true` / `false`   | 请求级 Mock 开关：`true` 本请求强制走剧本引擎（无需真实 LLM Key）；`false` 强制走真实模型；缺省回退全局 `COSY_AGENT_MOCK_ENABLED` |

请求头（可选）：

| 请求头           | 取值                 | 说明                                                                 |
| -------------- | ------------------ | ------------------------------------------------------------------ |
| `X-Cosy-Mock`  | `true` / `false`   | 请求级 Mock 开关：`true` 本请求强制走剧本引擎（无需真实 LLM Key）；`false` 强制走真实模型；缺省回退全局 `COSY_AGENT_MOCK_ENABLED` |
| `X-Cosy-Model` | `auto` / `平台/模型`  | 会话模型选择（模型路由 v2）：`auto` 走后端路由链（默认）；`平台/模型` 锁定单候选，不跨模型降级；缺省同 `auto`；Mock 开启时短路不参与路由 |

响应（`data` 为 `AgentResult`，结构见 [7.1](#71-agentresult)）：



```
{

&#x20; "code": 0,

&#x20; "message": "success",

&#x20; "data": {

&#x20;   "sessionId": "s1",

&#x20;   "answer": "任务已完成：{\\"zone\\":\\"Asia/Shanghai\\",\\"time\\":\\"2026-09-24 05:14:02\\"}",

&#x20;   "state": "COMPLETED",

&#x20;   "trace": \[

&#x20;     { "role": "USER", "content": "现在几点？", "toolCallId": null, "toolName": null, "toolArguments": null, "timestamp": "2026-09-24T05:14:02Z" },

&#x20;     { "role": "ASSISTANT", "content": "我需要调用工具继续处理。", "toolCallId": null, "toolName": null, "toolArguments": null, "timestamp": "..." },

&#x20;     { "role": "TOOL", "content": "{\\"zone\\":\\"Asia/Shanghai\\",\\"time\\":\\"...\\"}", "toolCallId": "call-1", "toolName": "get\_server\_time", "toolArguments": "{}", "timestamp": "..." },

&#x20;     { "role": "ASSISTANT", "content": "任务已完成：{...}", "toolCallId": null, "toolName": null, "toolArguments": null, "timestamp": "..." }

&#x20;   ],

&#x20;   "iterations": 4,

&#x20;   "costMs": 386,

&#x20;   "errorMessage": null,

&#x20;   "taskId": "task-1790198042033-1"

&#x20; }

}
```

要点：



* `taskId` 为持久化任务 ID（Step 6），可继续用于任务详情 / 断点恢复；

* `state` 取值见 `AgentState`：`COMPLETED` / `FAILED` / `TIMEOUT` 等；

* `trace` 完整记录 Thought→Action→Observation 推理链（合规审计）；

* 未配置真实 LLM Key 时（非 Mock 模式）返回 `state=FAILED`、`errorMessage` 描述原因，不崩溃。

### 5.1.1 模型路由管理 API（模型路由 v2）

模型路由配置**权威在后端**（`cosy.agent.model-routing.*` YAML 基线 + 持久化 store 覆盖），
管理 API 用于查询与热更新；客户端**不下发配置**，仅在会话界面提供 Auto / 指定模型选择器，
经 `X-Cosy-Model` 请求头传递选择。

#### GET `/api/agent/model-routing` — 查询当前配置

响应（`data` 为当前生效配置；api-key 一律脱敏）：

```
{
  "enabled": true,
  "maxCandidates": 5,
  "store": "memory",
  "platforms": {
    "openai":   { "baseUrl": "https://api.openai.com/v1", "apiKeyConfigured": true, "maskedApiKey": "sk-****xyz" },
    "deepseek": { "baseUrl": "https://api.deepseek.com/v1", "apiKeyConfigured": false, "maskedApiKey": null }
  },
  "routes": { "default": ["openai/gpt-4o-mini", "deepseek/deepseek-chat"] }
}
```

#### PUT `/api/agent/model-routing` — 更新配置（热生效）

请求体：`enabled` / `maxCandidates` / `platforms` / `routes`。
`apiKey` 传空或缺失表示**保持原值**；`store` 由服务端配置决定（memory / pg / mysql），不可经 API 切换。

```
{
  "enabled": true,
  "maxCandidates": 5,
  "platforms": {
    "openai":   { "baseUrl": "https://api.openai.com/v1", "apiKey": "sk-xxx" },
    "deepseek": { "baseUrl": "https://api.deepseek.com/v1", "apiKey": "" }
  },
  "routes": { "default": ["openai/gpt-4o-mini", "deepseek/deepseek-chat"] }
}
```

响应：更新后的配置（api-key 脱敏）；持久化失败返回 `code=10011`。

#### GET `/api/agent/model-routing/catalog` — 模型路由目录（客户端数据源）

响应（`data`）：`auto`（是否启用路由链）、`models`（全部路由链引用模型，去重、保序）、`routeTypes`（路由类型）。

```
{ "auto": true, "models": ["openai/gpt-4o-mini", "deepseek/deepseek-chat"], "routeTypes": ["default"] }
```

#### 路由与降级语义

* 候选链顺序即降级顺序（如 `default: [openai/gpt-4o-mini, deepseek/deepseek-chat]`：先 openai，失败切 deepseek）；
* 可降级异常：连接失败 / 调用超时 / HTTP 5xx / 429 / 熔断打开 → 自动切换下一候选；4xx 等客户端错误不降级直接失败；
* 全部候选失败 → `state=FAILED`，`errorMessage` 汇总各候选失败原因；
* 指定模型（`X-Cosy-Model: platform/model`）锁定单候选：该模型失败即失败，**不跨模型降级**；
* 平台未注册 → `code=10010`；`X-Cosy-Mock: true` 时短路走剧本引擎，不参与路由。

### 5.8 POST `/api/agent/tasks/{taskId}/resume` — 断点恢复

路径参数：`taskId`（源任务）。请求：



```
{ "message": "继续" }
```



| 字段      | 类型     | 必填 | 说明      |
| ------- | ------ | -- | ------- |
| message | string | 是  | 追加的用户输入 |

请求头（可选）：``X-Cosy-Mock: true|false``，语义与 5.1 一致（请求级 Mock 覆盖）。

行为：读取源任务的执行轨迹（USER/ASSISTANT/TOOL 消息）注入模型上下文后继续迭代，**产生新任务**；源任务保持不变。

响应：`data` 为 `AgentResult`，`taskId` 为新任务 ID（与源任务不同）。源任务不存在时返回 `10008`。

### 5.9 GET `/api/agent/sessions` — 会话列表

查询参数：

| 参数 | 类型 | 必填 | 默认 | 说明 |
| ---- | ---- | -- | -- | ---- |
| limit | int | 否 | 20 | 返回条数上限 |

响应（`data` 为 `SessionSummary[]`，会话=同一 sessionId 的任务分组，更新倒序）：

```
{ "code": 0, "message": "success", "data": [ { "sessionId": "s-49825923", "title": "现在几点了？", "state": "COMPLETED", "updatedAt": "2026-09-24T01:00:51Z" } ] }
```

| 字段 | 说明 |
| ---- | ---- |
| sessionId | 会话 ID |
| title | 会话名称（该会话最早任务输入，即首条消息） |
| state | 该会话最新任务状态 |
| updatedAt | 该会话最新任务更新时间 |

### 5.9.1 GET `/api/agent/sessions/{sessionId}` — 单会话摘要

路径参数：`sessionId`。响应（`data` 为 `SessionSummary`）：

```
{ "code": 0, "message": "success", "data": { "sessionId": "s-16cdfd19", "title": "现在几点了？", "state": "COMPLETED", "updatedAt": "..." } }
```

不存在时返回 `{ "code": 10009, "message": "会话不存在: <sessionId>" }`。客户端进入已有会话时以此恢复标题（会话名=首条消息）。

### 5.10 GET `/api/agent/sessions/{sessionId}/messages` — 会话全量消息

路径参数：`sessionId`。响应（`data` 为 `AgentMessage[]`，按消息时间戳升序合并该会话全部任务轨迹）：

```
{ "code": 0, "message": "success", "data": [ { "role": "USER", "content": "现在几点了？", "toolName": null, "timestamp": "..." }, ... ] }
```

客户端进入已有会话时以此恢复历史消息流（消息含 USER / ASSISTANT / TOOL 三类，TOOL 消息带 toolName/toolArguments）。

### 5.11 DELETE `/api/agent/sessions/{sessionId}` — 删除会话

路径参数：`sessionId`。行为：删除该会话全部任务与轨迹（`agent_task` / `agent_trace`），并联动清理 Redis 记忆（`cosy:work:{sessionId}:*`、`cosy:session:{sessionId}:*`）。会话不存在时静默成功。响应：

```
{ "code": 0, "message": "success", "data": true }
```

### 5.9 GET `/actuator/health` — 健康检查

已暴露端点：`health` / `info` / `metrics`。健康检查纳入 Redis（不可用时显示 `DOWN` 且记忆自动降级）与 Resilience4j 熔断器状态。



```
{ "status": "UP", "components": { "redis": { "status": "UP" }, ... } }
```

## 6. 数据模型

### 6.1 AgentResult



| 字段           | 类型              | 说明                                                                                                |
| ------------ | --------------- | ------------------------------------------------------------------------------------------------- |
| sessionId    | string          | 会话 ID                                                                                             |
| answer       | string \| null  | 最终回答（FAILED 时为 null）                                                                              |
| state        | string          | `AgentState`：INIT / PLANNING / RUNNING / TOOL\_CALLING / COMPLETED / FAILED / TIMEOUT / CANCELLED |
| trace        | AgentMessage\[] | 完整 ReAct 推理链                                                                                      |
| iterations   | int             | 实际迭代轮数                                                                                            |
| costMs       | long            | 执行耗时（毫秒）                                                                                          |
| errorMessage | string \| null  | 失败原因                                                                                              |
| taskId       | string \| null  | 任务 ID（Step 6 持久化后非空）                                                                              |

### 6.2 AgentMessage



| 字段            | 类型               | 说明                                       |
| ------------- | ---------------- | ---------------------------------------- |
| role          | string           | `SYSTEM` / `USER` / `ASSISTANT` / `TOOL` |
| content       | string \| null   | 文本内容（TOOL 时为工具返回结果）                      |
| toolCallId    | string \| null   | 工具调用 ID（TOOL 时非空）                        |
| toolName      | string \| null   | 工具名（TOOL 时非空）                            |
| toolArguments | string \| null   | 工具入参 JSON 字符串                            |
| timestamp     | string(ISO-8601) | 消息时间                                     |

## 8. 调用示例（curl / PowerShell）



```
\# 状态与工具

curl http://localhost:8080/api/agent/status

&#x20; -H 'Content-Type: application/json' \\

&#x20; -d '{"namespace":"hr","docId":"kb-1","content":"重置企业账号密码的操作步骤：..."}'

curl -X POST http://localhost:8080/api/agent/knowledge/search \\

&#x20; -H 'Content-Type: application/json' -d '{"namespace":"hr","query":"如何重置密码","topK":3}'

\# 任务审计与断点恢复

curl http://localhost:8080/api/agent/tasks/\<taskId>

curl "http://localhost:8080/api/agent/tasks?sessionId=demo-1"

curl -X POST http://localhost:8080/api/agent/tasks/\<taskId>/resume \\

&#x20; -H 'Content-Type: application/json' -d '{"message":"继续"}'

curl http://localhost:8080/actuator/health

curl -X PUT http://localhost:8080/api/agent/model-routing \
  -H 'Content-Type: application/json' \
  -d '{"enabled":true,"maxCandidates":5,"platforms":{"openai":{"baseUrl":"https://api.openai.com/v1","apiKey":"sk-xxx"}},"routes":{"default":["openai/gpt-4o-mini"]}}'

curl http://localhost:8080/api/agent/model-routing/catalog
```
