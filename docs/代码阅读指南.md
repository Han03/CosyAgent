# CosyAgent 服务端代码阅读指南

> 目标：让读者**一步一步**熟悉整个项目。每步给出：看哪些文件（按顺序）、理解什么、关键概念、下一步衔接。
> 建议配合 IDE（IntelliJ）阅读，从 `Call Hierarchy` / `Find Usages` 追踪调用链。
> 全程主线只有一条：**一次 HTTP 请求 → 编排装配 → ReAct 循环 → 任务落库 → 流式返回**。

---

## 0. 项目全景

| 维度 | 说明 |
| --- | --- |
| 技术栈 | Spring Boot 3 + Spring AI 1.1.8 + Redis + PostgreSQL(pgvector) + Resilience4j + MySQL |
| 核心思想 | ReAct（Thought→Action→Observation）循环，LLM 自主规划与工具调用 |
| 代码规模 | 60 个 Java 类，分层：controller → service → agent.*（能力层）→ config/common/security |
| 模块映射 | Step 1 框架 / Step 2 ReAct / Step 3 Redis 记忆 / Step 4 PGVector RAG / Step 5 容错 / Step 6 状态机 / Step R 模型路由 / Mock 引擎 |
| 入口命令 | `mvn clean spring-boot:run`（8080） |
| 测试门槛 | `mvn test` 87 项全绿 + BUILD SUCCESS |

**一次请求生命周期（先建立全局图）：**

```
客户端 POST /api/agent/chat/stream
   → AgentController.chatStream           [controller] 解析请求头(X-Cosy-Mock / X-Cosy-Model)
   → AgentOrchestrator.chat               [service]    加载历史→登记任务→构造上下文
   → DefaultReActAgent.run                [agent.core] Thought→Action→Observation 循环
        ├─ ModelRouter.call                [agent.router] 候选链解析→调 LLM→失败降级
        │     └─ MockScriptEngine.generate [agent.mock]   Mock 开启时不走真实平台
        ├─ ToolRegistry → AgentTool.execute [agent.tool]  模型选择的工具
        ├─ RedisMemoryStore                [agent.memory] 历史记忆读写
        └─ VectorKnowledgeStore.search     [agent.vector] 知识增强(RAG)
   → TaskStore 落库(任务+轨迹)             [agent.task]  终态 COMPLETED/FAILED/TIMEOUT
   → SSE 事件流回客户端                     [AgentStreamEvent]
```

每个包入口都有 `package-info.java`，内含**包职责 + 包内阅读顺序**，是每步的导航。

---

## 第 1 步：启动入口与配置

**文件（按序读）：**
1. `CosyAgentApplication.java` —— 启动类：`@SpringBootApplication` + `@EnableConfigurationProperties`（决定哪些配置类生效）
2. `src/main/resources/application.yml` —— 全局配置（重点看 `cosy.agent.*` 段）
3. `config/AgentProperties.java` —— 核心配置 record：`maxIterations`（迭代上限）、`toolTimeout`、`sessionTimeout`、`mock.*`、`resilience.*`
4. `config/AgentChatConfig.java` —— Bean 装配：`agentChatOptions` 把工具桥接（AgentToolBridging）注入模型 ChatOptions；`agentContextFactory` 构造运行上下文

**理解要点：**
- 配置是 record（不可变），前缀 `cosy.agent`，环境变量可覆盖（`${...:默认值}`）
- Mock 开关 `cosy.agent.mock.enabled` 默认 **false**（真实模型）；`X-Cosy-Mock` 请求头可请求级覆盖
- 工具定义在**装配期**就注入模型选项，模型才"知道"有哪些工具可用

**下一步：** 配置好上下文，去看谁消费这些配置 → 第 2 步入口。

---

## 第 2 步：HTTP 入口层（controller）

**文件（按序读）：**
1. `controller/AgentController.java` —— 主入口。重点方法：
   - `chat`（同步 POST /api/agent/chat）
   - `chatStream`（**SSE 流式 POST /api/agent/chat/stream，全项目最佳阅读起点**）
   - `sessions / session / sessionMessages / task / resume / deleteSession / tools`
2. `controller/KnowledgeController.java` —— 知识库 upsert / search

**理解要点：**
- Controller 只做三件事：**解析请求头 → 调 Orchestrator → 包装 Result/SSE**，无业务逻辑
- 请求头语义：`X-Cosy-Mock`（Mock 覆盖）、`X-Cosy-Model`（auto | 平台/模型）、`X-Cosy-API-Key`（鉴权）
- SSE 返回用 `SseEmitter`；事件由 `AgentEventListener` 回调产生（见第 4 步）

**下一步：** Controller 把所有活儿委托给 AgentOrchestrator → 第 3 步。

---

## 第 3 步：编排层（service）

**文件：** `service/AgentOrchestrator.java`

**核心方法（按序读）：**
- `chat(sessionId, userId, input, mockOverride)` / `chat(..., modelChoice)` —— 主流程
- `resume(sourceTaskId, input, mockOverride)` —— 断点续跑（读历史轨迹注入上下文后继续）

**理解要点（方法体里发生了什么）：**
1. 解析会话：加载历史记忆 / 会话标题
2. 构造 `AgentContext`（会话、用户、迭代上限、任务 id、Mock 覆盖、模型选择）
3. 登记任务：`TaskStore.createTask`（INIT→RUNNING）
4. 调 `reactAgent.run(context, input, history, listener)` 执行 ReAct 循环
5. 落终态 + 轨迹审计：`appendTrace`（COMPLETED / FAILED / TIMEOUT）
6. **关键设计**：任务持久化失败不阻断对话（仅告警）——存储故障不雪崩主链路

**下一步：** 真正的核心在 `reactAgent.run` → 第 4 步 ReAct 大脑。

---

## 第 4 步：ReAct 核心（agent.core，本项目大脑）

**文件（按序读）：**
1. `AgentContext.java` —— 一次运行的上下文（record）：sessionId/userId/maxIterations/taskId/mockOverride/modelChoice
2. `ReActAgent.java` —— 执行器契约（接口，3 个 `run` 重载）
3. **`DefaultReActAgent.java` —— 核心实现（最重要，逐段读）**：
   - `run` 三级委托（run → run(context,input,history) → run(context,input,history,listener)）
   - **循环主体**：`while` 迭代 →
     a. 组装 Prompt（系统提示 + 记忆历史 + RAG 命中注入）
     b. `ModelRouter.call` 调 LLM（见第 8 步）
     c. 解析响应：有 toolCalls → 发 `tool` 事件 → 执行工具 → 发 `toolResult` 事件 → 继续循环；
        无 toolCalls → 发 `answer` 事件 → 结束
     d. 触发终止：达到 `maxIterations` → TIMEOUT
   - 事件发射：`AgentStreamEvent`（thinking/reasoning/tool/toolResult/answer/done）
   - 自愈：未知工具名时走"自愈路径"（可配置关闭）
4. `AgentStreamEvent.java` —— SSE 事件协议（**客户端渲染的依据**，字段即协议）
5. `AgentMessage.java` / `AgentResult.java` / `AgentState.java` / `AgentEventListener.java` —— 数据与回调契约

**理解要点：**
- 这个类把"模型规划"与"工具执行"串成循环；**读懂循环 = 读懂项目一半**
- `AgentStreamEvent` 的 13 个字段就是 SSE 协议本身，与客户端 `agent_stream_event.dart` 一一对应
- 配套测试：`DefaultReActAgentTest`（事件序列/自愈/循环上限等 87 项之一）

**下一步：** 循环里两个关键依赖：工具从哪来、模型从哪来 → 第 5 步工具层、第 8 步模型路由。

---

## 第 5 步：工具层（agent.tool）

**文件（按序读）：**
1. `AgentTool.java` —— 工具契约接口：`name/description/parameters/execute/retryable`
2. `ToolRegistry.java` —— 注册表：Spring 自动收集 `List<AgentTool>` + 手工 `register`
3. `ServerTimeTool.java` / `ServerInfoTool.java` —— 两个示例工具（读一个就懂怎么写新工具）
4. `AgentToolBridging.java` —— 桥接：`AgentTool` → Spring AI `OpenAiApi.FunctionTool`（JSON Schema）

**理解要点：**
- **新加工具 = 实现 AgentTool + 交给 Spring 容器**，零额外改动（工具自动进入 LLM 视野）
- 桥接层在装配期把工具定义注入 ChatOptions；执行期由 `DefaultReActAgent` 按名从注册表查找执行
- 工具超时/限流由 Resilience4j 包（ResilienceTarget.TOOL，见第 9 步）

**下一步：** 循环每轮还要加载记忆 → 第 6 步。

---

## 第 6 步：记忆层（agent.memory）

**文件（按序读）：**
1. `MemoryLevel.java` —— 记忆层级枚举（如 SESSION / USER）
2. `MemoryRecord.java` —— 记录（level + namespace + key + value + ttl）
3. `MemoryStore.java` —— 接口：save / load / delete / deleteNamespace / list
4. `RedisMemoryStore.java` —— Redis 实现：键形 `cosy:{level}:{namespace}:{key}`，TTL 分层

**理解要点：**
- 记忆 = **带 TTL 的键值**，不是数据库表；Redis 天然支持过期
- 被 `DefaultReActAgent` 每轮加载（历史上下文）与完成后回写
- 故障不影响对话（ResilienceTarget.MEMORY 容错包裹）

**下一步：** 除了对话记忆，还有知识记忆 → 第 7 步。

---

## 第 7 步：向量检索层（agent.vector，RAG）

**文件（按序读）：**
1. `Vectorizer.java` —— 向量化接口
2. `DeterministicVectorizer.java` —— 确定性实现：2-gram 哈希词袋 + L2 归一化（256 维，CI 可复现；生产换 EmbeddingModel 同接口）
3. `DocumentChunker.java` —— 文档切块（chunkSize + overlap）
4. `VectorKnowledgeStore.java` —— 存储接口：upsert / search
5. `InMemoryKnowledgeStore.java`（默认） / `PgVectorKnowledgeStore.java`（生产，pgvector 余弦距离）

**理解要点：**
- RAG 链路：**入库**（Controller → chunker 切块 → vectorizer 向量化 → upsert）与**检索**（query 向量化 → 余弦 TopK + 阈值）
- 被 `DefaultReActAgent` 运行前检索，命中注入系统提示（知识增强）
- 两个实现同接口切换：`cosy.agent.vector.store=memory|pgvector`

**下一步：** 循环里调 LLM 是怎么选模型的 → 第 8 步模型路由。

---

## 第 8 步：模型路由（agent.router，Step R）

**文件（按序读）：**
1. `RouteConfig.java` —— 配置模型：平台（baseUrl/apiKey/completionsPath）+ 路由链（default/reasoning）+ 候选解析
2. `ModelRoutingConfigStore.java` + 三个实现（InMemory / Jdbc / Mysql）—— 配置持久化
3. `ModelPlatformRegistry.java` —— ChatModel 工厂：按平台延迟构建 + 缓存，配置变更自动重建
4. **`ModelRouter.java` —— 核心**：`call(prompt, modelChoice)` →
   - 解析候选链（auto 走 default 链；`平台/模型` 锁定单候选）
   - 逐个调用（套 LLM 容错），可降级异常（连接失败/超时/5xx/429/熔断）切下一候选；**4xx 不降级**
   - Mock 开启时短接 `MockScriptEngine`（见第 11 步）
5. `ModelRoutingAdmin.java` —— 管理 API：GET/PUT 配置（api-key 脱敏）、catalog（客户端模型选择器数据源）
6. `RouteResult.java` —— 路由结果（响应 + 命中候选 + 降级链）

**理解要点：**
- **配置权威在后端**：YAML 基线 + 管理 API 热更新（`refresh` 清平台缓存即时生效）
- 请求头 `X-Cosy-Model: auto | platform/model` 是客户端"指定模型"的唯一通道
- completions-path 差异（智谱/火山无 `/v1`）通过配置解决，不硬编码

**下一步：** LLM 与工具调用都有容错 → 第 9 步。

---

## 第 9 步：容错层（agent.resilience，Step 5）

**文件（按序读）：**
1. `ResilienceTarget.java` —— 四类落点枚举：LLM / TOOL / MEMORY / VECTOR / TASK
2. `ResilienceSupport.java` —— 统一执行器：`execute(target, supplier)` 施加组合策略
   （Retry → CircuitBreaker → RateLimiter → Bulkhead → TimeLimiter，外→内）

**理解要点：**
- 全项目"外部调用"都走这一个入口，策略在 `application.yml` 的 `resilience4j.*` 声明式配置
- 降级语义：熔断打开返回友好文案，不雪崩；LLM 降级见第 8 步候选切换
- 阅读时注意各 Store（Redis/PG/MySQL）如何用 `ResilienceSupport.execute(ResilienceTarget.X, ...)` 包裹

**下一步：** 对话/任务要持久化才能断点续跑 → 第 10 步。

---

## 第 10 步：任务状态机（agent.task，Step 6）

**文件（按序读）：**
1. `AgentTask.java` —— 任务记录（含状态机字段）
2. `TaskStore.java` —— 接口：createTask / appendTrace / findById / findBySession / findSession / deleteSession，内嵌 `SessionSummary` / `TaskDetail`
3. `InMemoryTaskStore.java`（默认）→ `JdbcTaskStore.java`（PG）/ `MysqlJdbcTaskStore.java`（MySQL）—— 条件装配（`cosy.agent.task.store`），启动自建表

**理解要点：**
- 状态机：INIT → RUNNING → COMPLETED / FAILED / TIMEOUT（`AgentState`）
- 会话/任务/消息/置顶/重命名/删除 全在这里；**客户端会话列表与历史消息的数据源**
- 断点续跑：`resume` 读取历史轨迹注入上下文继续 → 新任务
- 存储故障不阻塞对话（容错 + 告警降级）

**下一步：** 不接真实 LLM 时怎么完整跑通？→ 第 11 步 Mock。

---

## 第 11 步：Mock 引擎（agent.mock）

**文件（按序读）：**
1. `MockTurnType.java` / `MockTurn.java` / `MockAction.java` —— 回合建模（TOOL_CALL / FINAL_ANSWER / RAISE_ERROR）
2. `MockScript.java` / `MockScriptLibrary.java` —— 剧本与剧本库（time / combined / server-info / self-heal / loop-limit）
3. `MockRandomSource.java` —— 随机源（scripted 固定种子可复现；random 用户消息哈希锚定）
4. `MockScriptEngine.java` —— 引擎：`generate(Prompt)` 按剧本推进回合 + 注入随机性 + 模拟延迟，产出 `ChatResponse`

**理解要点：**
- Mock 开启 = **不经真实平台**，完整模拟 ReAct（工具调用/自愈/循环上限/500-2500ms 延迟）
- 剧本选择：关键词优先（"时间"→time 剧本），否则按输入哈希加权随机
- 随机性设计：`chance(prob)` 注入错误/多工具/额外回合，演示容错与多轮

**下一步：** 所有接口返回什么形状？→ 第 12 步统一协议。

---

## 第 12 步：统一协议与安全（common / security）

**文件（按序读）：**
1. `common/api/Result.java` —— 统一响应 `{code, message, data}`（code=0 成功）
2. `common/enums/ErrorCode.java` —— 错误码枚举
3. `common/exception/BizException.java` —— 业务异常
4. `common/exception/GlobalExceptionHandler.java` —— 全局异常 → Result（不泄露异常细节）
5. `security/ApiKeyFilter.java` —— API Key 鉴权（`X-API-Key`，配置为空不注册，actuator 放行）

**理解要点：**
- 所有 REST 接口返回 Result；SSE 接口例外（走 `AgentStreamEvent` 事件流）
- 业务错误：抛 BizException(ErrorCode) → 全局处理器统一转 Result
